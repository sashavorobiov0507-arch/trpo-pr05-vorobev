# Практическая работа 5. PHP ООП

Каталог товаров на PHP с классами Product, Category и CatalogService

## Что делает программа

Читает товары и категории из json-файлов, делает из них объекты и показывает на странице карточками, товары можно отфильтровать по категории и по наличию, сверху показывается сколько товаров найдено и их средняя цена

## Чем сделано

PHP 8.1 и выше, HTML, CSS
Запускается встроенным сервером PHP, ничего больше устанавливать не надо

## Как запустить

Нужен установленный PHP (проверить командой `php -v`)

В PowerShell в папке проекта:

```
php -S 127.0.0.1:8080 -t public
```

Потом открыть в браузере:

- http://127.0.0.1:8080/ - каталог
- http://127.0.0.1:8080/check.php - проверка конструкторов

## Структура проекта

```
data/            products.json, categories.json, class_requirements.csv
public/          index.php, check.php, style.css
src/Model/       Product.php, Category.php
src/Service/     CatalogService.php
```

## Схема

```
Product -> CatalogService -> index.php
```

Product (и Category) хранят данные одного товара или категории и проверяют их в конструкторе 
Если данные неправильные, выбрасывается InvalidArgumentException

CatalogService читает products.json и categories.json, создаёт объекты, фильтрует их по категории и считает среднюю цену и количество

index.php получает данные из формы фильтра, вызывает сервис и выводит HTML
Все значения экранируются через htmlspecialchars

## Как проверить

1. Открыть главную, должно быть 12 товаров, два из них (5 и 10) недоступны.
2. Выбрать категорию и нажать "Применить", список станет меньше.
3. Поставить галочку "Только доступные", недоступные пропадут.
4. Открыть `/?category=abc`, появится предупреждение и покажется весь каталог.
5. Открыть `/check.php`, там видно, что неправильные данные в конструкторах вызывают ошибку.

## Что изменилось после шага 4

В классе Product добавил методы belongsToCategory(), priceWithDiscount(), formattedPrice() и statusLabel()
Теперь форматирование цены и текст статуса делает сам класс, а не HTML

## Про require_once

Классы подключаются вручную через require_once, пока файлов три, это нормально
Когда классов станет много, придётся в каждом файле писать длинный список require_once, легко забыть один или перепутать порядок, поэтому в больших проектах используют автозагрузку (Composer, PSR-4), чтобы классы подключались сами
